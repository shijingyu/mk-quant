# MySQL 与 Parquet 存储

平台运行、开发与集成验证统一使用 MySQL，所有业务表显式为 InnoDB。没有 SQLite 或内存数据库回退；旧文件库仅由隔离的单次迁移工具只读打开，不进入应用运行路径。

## 环境与事务规则

当前部署基线为 MySQL 5.7.44，与宝塔实际安装版本一致；开发与集成 Compose 也固定同一版本。`backend/schema.py` 是共同 schema；每个连接设置 `utf8mb4`、UTC 会话时区、READ COMMITTED 隔离和严格 SQL 模式。`schema_migrations` 记录建表及一次性导入版本。未来升级数据库版本时，先在隔离库运行相同集成测试并验证迁移和恢复，再同步更新开发、集成、生产及两份 Compose 配置；不跳过数据库测试或用模拟库替代。

每个环境使用独立数据库、独立用户和独立文件目录。专用用户只拥有自身业务库权限；测试清理需要数据库名以 `_test` 结尾并设置 `MK_TEST_ALLOW_RESET=1`，生产库不允许此标记。MySQL 不开放公网端口。

| 配置 | 含义 |
| --- | --- |
| `MK_DB_HOST`, `MK_DB_PORT` | 必填主机，端口默认 3306。 |
| `MK_DB_NAME`, `MK_DB_USER`, `MK_DB_PASSWORD` | 必填专用业务库及凭据。 |
| `MK_DB_SSL_MODE` | 仅支持 `disabled`、`verify_identity`。回环/SSH 隧道默认 `disabled`，非回环默认 `verify_identity`；隔离 Docker 内网可显式设为 `disabled`。 |
| `MK_DB_SSL_CA` | 远程连接的可信 CA 文件，校验证书及主机身份。 |
| `MK_ARTIFACT_ROOT` | Parquet 根目录；未设置时为工作目录下的 `data/artifacts`。部署时显式配置绝对路径，API 与任务进程都需可读，写入进程需可写。 |

数据库名只允许字母、数字和下划线，最长 64 字符。回环默认值仅指连接到本机或本机 SSH 转发端口，跨主机不应关闭身份校验。配置只读取进程环境。复制 `.env.example` 不能代替把环境交给启动进程；不要把真实密码写入命令行参数、日志或 Git。宝塔通过每个 Python 项目的环境文件加载。

## 核心业务表

| 数据 | 表与约束 |
| --- | --- |
| 用户及登录 | `users`、`sessions`；登录名唯一，会话关联用户，密码哈希持久化。 |
| 账户与实例 | `accounts`、`instances`、`account_execution_settings`（账户目标杠杆）；账户一个实例、实际交易身份唯一、随机客户路由唯一。 |
| 策略 | `strategies`、`strategy_versions`、`strategy_archives`（删除标记与操作人）；按源码哈希固定不可变版本，实验携带版本及内容哈希。 |
| 控制与状态 | `commands`、`services`、`runtime_events`；请求、回执、心跳及停止状态持久化。 |
| 订单与成交 | `orders`、`fills`；账户范围幂等标识、外键，成交金额使用 DECIMAL。 |
| 资金账本 | `ledger`；成交、估值和恢复快照持久化，引用键唯一。 |
| 审计 | `audit_records`；账户/配置/策略/实验/命令等变更与业务写入在同一事务提交，凭证不写入审计内容。 |
| 历史与实验 | `datasets`、`experiments`、`presets`；参数、区间、版本、费用模型、统计及文件清单。 |
| 辅助数据 | `market_cache` 保存运行期共享行情窗口；`logs` 保存调试与错误；`binance_order_intents` 保存交易所请求幂等状态。 |

实例接管通过 `SELECT … FOR UPDATE` 锁定实例行并递增 fencing token。运行进程写入前再次验证持有人、token、租约与目标状态；订单、成交、账本、账户快照及回执在同一事务中持久化。唯一键避免重复成交与重复实际账户绑定。交易所结果未知时不自动重发。

## 历史与大明细文件

`backend/storage.py` 将历史 K 线、回测完整权益曲线、订单和决策保存为独立 Parquet，使用 Zstandard 压缩。K 线有交易对、毫秒时间戳和 OHLCV 分析列，另保留精确 JSON 记录以无损回放。

文件按内容哈希定位，先写临时文件、fsync，再通过硬链接无覆盖发布不可变文件并同步目录，最后提交 MySQL 清单。根目录需使用支持这些操作的文件系统，不能直接替换成对象存储 URL。清单包含格式版本、相对路径、文件 SHA-256、内容哈希和行数；K 线清单另含交易对及起止时间。读操作拒绝越界路径、缺失文件和校验不符；相同内容重复发布也会检查已有文件实际内容。失败事务可能留下未引用文件，不会发布部分文件引用；目前不自动垃圾回收，以免误删实验版本。

回测列表和运行视图只传摘要及分桶最小/最大值预览；界面标注抽样，未做平滑。完整统计使用全部数据，详情和导出回读原始明细。当前大明细详情仍整段加载，分页读取基础已具备；非常大的单次详情仍需控制浏览器容量。

时间戳与存储版本不随浏览器时区改变。页面的行情、回测区间、实验创建/执行/完成、订单及决策时间按北京时间显示。每日/月度收益的已有 UTC 结算口径保持不变。

## 开发与集成验证

已有 MySQL 可直接创建三个独立环境库。也可使用仓库的 `compose.database.yaml`，设置私有 `MK_DB_PASSWORD` 和不同的 `MK_DB_ROOT_PASSWORD` 后启动：

```bash
docker compose -f compose.database.yaml up -d
```

开发连接本机 3307，库名和用户为 `mk_quant_dev`；集成连接 3308，库名和用户为 `mk_quant_test`。为开发、测试分别设置相应的 `MK_DB_*` 变量与独立 `MK_ARTIFACT_ROOT` 后，运行 `./scripts/dev.sh` 或测试。`.env` 不由应用自动加载；应在启动 shell 或进程管理器中显式导出：

```bash
# 仅限隔离的 _test 数据库
export MK_TEST_ALLOW_RESET=1
.venv/bin/python -m pytest -q
```

测试覆盖真实事务回滚、外键/唯一约束、并发租约接管、重复订单意图、策略版本不可变、账户权限、子进程回测/模拟及 Parquet 丢失/篡改检查。测试会清理专用测试库；不能与其他测试进程共享同一库并行运行。

## 既有数据单次迁移

1. 停止所有旧写入进程，取得一致性旧库备份并校验完整性，保存原代码与私有环境。
2. 在宝塔新建独立 MySQL 业务库，配置专用用户。目标必须为空；不覆盖已有业务库。首次导入前不要启动应用、初始化演示数据或创建管理员，以免预置记录占用空目标。
3. 在相同 MySQL 版本的开发库演练，再对停止写入后的最终备份执行正式迁移。
4. 配置新 MySQL 和文件目录环境，运行离线迁移工具。先不加 `--apply` 查看计划，确认数据表映射后执行：

```bash
python scripts/migrate_sqlite_to_mysql.py --source /private-backup/legacy.sqlite3 --apply --report /private-backup/migration-report.json
```

工具仅只读访问旧文件，逐表保留所有原始记录，校验行数与字段值，回填 Parquet 并回读比较，补齐策略版本与订单/成交，最后验证所有表为 InnoDB。迁移标记支持同一份备份失败后重试；未匹配导入标记的非空目标、未知旧表均拒绝继续。迁移及重试全过程保持目标停写，完成并启用业务写入后不再对该目标重跑原始导入。

5. 文件目录归运行用户所有（目录 750、文件 640），切换三个服务环境，启动新服务并验收登录、客户权限、历史实验导出、独立回测及命令回执。
6. 旧文件移出活动项目目录，作为私有回退证据保留。正式运行不再读取或写入它。若切换后已有新交易记录，不能直接回退旧备份丢弃这些写入，须停写并对账。

## 联合备份与恢复

在已安装本项目 Python 依赖且正确加载业务环境的进程中运行 `python deploy/backup.py`。备份使用兼容版本的 `mysqldump --single-transaction` 获取 InnoDB 一致性快照，再收集不可变 Parquet。它检查数据库引用及文件校验和，只纳入发布后的内容哈希文件，排除 `.writing-*` 临时文件并拒绝符号链接。

每份权限 600 的归档包含 `database.sql.gz`、`artifacts/` 和 `manifest.json`；清单记录压缩 SQL 及每个文件的 SHA-256，命令输出整体归档校验和。临时目录权限 700，凭证通过权限 600 的临时 MySQL 选项文件传给工具，不进入参数。`mysqldump` 与应用采用同一 `MK_DB_SSL_MODE` / `MK_DB_SSL_CA` 规则，远程数据库要求 `VERIFY_IDENTITY`，客户端需支持相应选项。Fernet 主密钥单独保管，归档不含环境文件。

恢复时停止写入，先核对归档及清单哈希，在空的隔离 MySQL 库解压导入 `database.sql.gz`，将 `artifacts/` 的内容恢复到 `MK_ARTIFACT_ROOT`，配置运行用户的读写权限。核对表的 InnoDB 引擎、关键行数、文件清单和数据库引用，再进行历史结果回读、回放及权限验收。迁移到另一个数据库名时，更新连接配置；文件清单使用相对路径，恢复时不改变其子目录结构。联合备份通过文件生命周期锁与发布、删除互斥；备份期间仍不能做 DDL 或绕过框架手动删文件。宝塔的单库备份可额外保留，但单独一份 MySQL SQL 文件不能恢复完整历史研究数据。

## 磁盘与 MySQL 二进制日志

MySQL 二进制日志独立于业务表大小；反复写入行情窗口等大字段，会使小型业务库生成大量日志。共享行情仅在内容或交易规则变化时写入大字段，其余成功轮询只更新时间，不改变数据过期判断或分钟撮合频率。

运维需同时监测磁盘剩余空间、inode、二进制日志增长和备份容量。磁盘写满出现 errno 28 时，先释放可再生缓存并校验一致性备份，检查复制与恢复依赖，再经管理员确认使用 `PURGE BINARY LOGS` 清理备份坐标之前的日志；不要直接删除数据目录中的文件。日志保留期限须匹配恢复目标，MySQL 5.7 使用 `expire_logs_days`，同时更新运行值和配置文件；日志轮转时才触发过期清理，`max_binlog_size` 可限制单文件的通常规模（大事务仍可能超限）。缩短保留期会缩短可按时间点恢复的范围，不能代替数据库与 Parquet 联合备份。

空间恢复后检查受影响账户的持久快照、仓位、挂单和命令回执，再恢复因本次错误停止的账户；不要批量启动原本由管理员停止的账户。

## 数据集删除

`DELETE /api/datasets/{id}` 仅管理员可调用，并要求 CSRF。对数据集行加锁后检查实验引用；有引用返回 409，新实验入队也锁定数据集，避免并发悬空引用。未引用数据集从目录删除，下载任务保留并清空 dataset_id，审计保留内容哈希和文件清单。

`DELETE /api/experiments/{id}` 使用相同权限校验，仅删除 completed、failed、cancelled 状态的实验，保留原始 K 线及策略版本。删除记录释放该实验的数据集引用；曲线、验证曲线、订单与决策明细进入文件清理流程。排队、运行或取消请求尚未确认的实验返回 409。

删除事务同时写入 `artifact.cleanup.pending` 审计事件；事务成功提交后才清理文件。回收时重新检查全部数据集与实验的存活引用，共享文件保留到最后一份引用删除。清理限制内容寻址路径，拒绝符号链接、越界路径或校验失败的文件；重复清理已不存在的文件视为成功。失败保持待重试，API 启动时自动重试；审计中的 cleanup.complete / cleanup.retry 记录释放字节数及共享文件数。返回值中的 freed_bytes 是本次实际删除字节数，不估算文件系统剩余容量。

所有角色必须共享同一 `MK_ARTIFACT_ROOT`，其文件系统必须支持 `flock`。文件发布直到数据库引用提交、删除及回收、联合备份全过程使用同一根目录生命周期锁，防止并发发布与清理竞态；长时间下载本身不持锁。锁随进程退出自动释放，运行交易进程不依赖该锁。联合备份归档包含独立文件副本，不受在线文件删除影响；恢复必须同时恢复 SQL 和 Parquet，不能只恢复宝塔单库备份。不要手工删除根目录或绕过此锁回收文件。


回测的 `.research-<pid>-*` 为非业务临时存储：压缩记录块和固定大小哈希索引，不使用 SQLite，不作为账本或审计的唯一保存位置。完成后仍发布同一 Parquet 清单协议；正在运行的图表是有限真实极值预览，最终统计按全部记录顺序计算。正式结果文件发布失败或取消时，通过持久清理任务回收无引用文件。

### v1.6.0 增量表

启动时创建 InnoDB 表 `account_execution_settings` 和 `strategy_archives`，不重写既有账户、账本或策略版本。杠杆设置与账户更新、配置修订号和审计在同一事务提交；缺少设置的既有账户沿用策略声明的最低杠杆。删除策略采用持久删除标记，保留实验外键和版本快照；新建账户、保存预设及创建实验与删除操作共用策略行锁，避免删除与引用并发竞争。

v1.6.1 新增 InnoDB 表 `account_archives`，记录账户删除标记、操作人和时间。账户删除与凭证清除、会话撤销、执行租约失效及审计在同一事务提交，历史账本外键不变。
