# BTCUSDC / ETHUSDC 比值均值回归

策略源码：[btc_eth_usdc_ratio.py](../backend/strategies/btc_eth_usdc_ratio.py)。内置 ID 为 `btc_eth_usdc_ratio`，显示名称为“BTC/ETH 比值回归 · USDC”。默认使用 Binance USDⓈ-M 的 BTCUSDC、ETHUSDC 永续，主周期为 **1h**，参数为 **168 / 3 / 0.25**。本实现用于框架内回测和持续模拟，真实下单入口保持关闭。

## 策略怎么算

每根完整主周期 K 线收盘后，计算原始收盘价比值 `R = BTCUSDC.close / ETHUSDC.close`。最近 `lookback` 根包含当前已闭合 K 线，以总体标准差（`ddof=0`）计算 `Z = (R - mean(R)) / std(R)`。窗口随时间移动，两腿历史必须同时间戳、连续且包含当前闭合 K 线。历史不足、缺口或标准差为零时等待。

| 条件 | 操作 |
| --- | --- |
| 空仓，`Z < -entry_z` | 多 BTCUSDC、空 ETHUSDC |
| 空仓，`Z > entry_z` | 空 BTCUSDC、多 ETHUSDC |
| 已持有完整配对，`abs(Z) < exit_z` | 平掉两腿 |
| 等于阈值，或直接跳过离场带 | 不触发相应交易 |

没有额外止损、穿零退出或最长持仓期限。持仓期间不重新平衡数量。同一批交易意图不会平仓后立即反手。退出一旦触发，`exit_pending` 会保存到持久状态，之后每次主周期回调继续只减仓，直到两腿实际全平；即使 Z 已离开退出带也不会撤销退出意图。这是处理未成交的执行规则。

## 配置与成本

| 配置 | 默认值及含义 |
| --- | --- |
| 主周期 | `MANIFEST.timeframes.primary = "1h"` |
| `lookback` | 168 根主周期 K 线，默认约 7 天 |
| `entry_z` / `exit_z` | 3 / 0.25，且离场阈值须小于入场阈值 |
| 初始资金 | 可用 10,000 U；策略最低资金 1,000 U |
| 账户 | 单向持仓、全仓；回测杠杆可选 2–100 倍，默认 2 倍 |
| 目标总名义额 | 决策时权益的 1 倍，两腿各 50% |
| 模拟成本 | `execution.paper_costs = {"fee_rate": 0.0, "slippage_bps": 0.0}` |
| 回测成本 | 在回测表单中手动将手续费率与滑点均设为 0 |

**账户杠杆影响保证金占用；策略的目标总名义额仍是权益 1 倍。** 把回测杠杆改为 100 不会自动把两腿仓位扩大 100 倍。持续模拟目前按策略声明的最低杠杆 2 倍初始化账本。数量按信号 K 线收盘价计算，随后由框架按 LOT_SIZE 与 MARKET_LOT_SIZE 的保守交集向下取整，检查数量与开仓最小名义额。买价向上、卖价向下对齐 tick；已在 tick 上的价格不会额外增加固定滑点。减仓不因小额最小名义额限制而阻塞。

实际成交采用下一分钟开盘价，所以跳空可使实际总名义额偏离 1 倍。价格还必须位于该分钟 `[low, high]` 且成交量大于零；不满足时拒绝成交。框架是逐腿顺序执行，不是原子双腿交易；一腿可能成功而另一腿失败。策略在下一主周期回调发现单腿或双腿同向时优先只减仓，不补开缺失腿。默认 1h 下残腿通常要等到下一小时回调才处理；停机、行情缺失或持续拒单时可能更久。15m、4h、1d 变体的反应时间随主周期变化。

## 在框架里回测

1. 更新本次涉及的框架后端代码并重启相关 API、回测和模拟服务。零成本持续模拟依赖新版 `backend/strategy.py` 与 `backend/worker.py`；**只向旧框架上传新策略不会更新 worker，旧版本仍可能按默认 4 bp 手续费、2 bp 滑点运行**。
2. 在“策略管理”上传或粘贴上述 `.py` 源码，保存后选择该策略。管理员正常上传通过契约校验后即按可信代码启用，不需要额外审批。上传记录会取得新的数据库 ID，与源码中的内置 ID 可以不同。若已使用新版内置策略，可直接选择内置记录。
3. 在行情管理下载 **futures、BTCUSDC 与 ETHUSDC、原生 1m** 数据，两腿必须覆盖相同且连续的分钟区间。不要上传 1h 数据冒充分钟数据。
4. 回测选择该双币数据集，设初始资金 10,000 U、杠杆 2、手续费率 0、滑点 0，参数使用 168 / 3 / 0.25。框架从连续分钟合成完整 UTC 1h K 线，仅在完整主周期收盘时产生信号；订单在下一分钟开盘撮合。
5. 训练段与验证段各自从全新策略和账户开始，分别预热，不自动承接前一段的历史、仓位或状态。因此每段开头须留足完整主周期历史，不能把整个所选区间视为均已可交易。`lookback` 指主周期根数，不是分钟数。

策略 v1.0.1 将账户杠杆上限从 2 放宽至 100，最低杠杆仍是 2。已有数据库中的旧策略源码不会因替换项目文件而自动更新；请重新上传新版 `.py` 并在工作台选择新的策略记录。历史实验和旧记录保留原版本。CLI 也支持 `--leverage 100`，未指定时使用 2。

回测工作台“另存为”现在同时保存策略参数和“资金与费用”中的初始资金、杠杆、手续费率、滑点。加载新预设会恢复这四项，包含数值 0；旧预设仅恢复策略参数，保留当前资金费用设置。数据集、币种和训练/验证日期不随参数预设改变。前后端需一起更新，后端启动时会为 `presets` 表新增可空的 `backtest_config` 字段，保留已有预设。

源码实现支持 `15m / 1h / 4h / 1d`，默认 manifest 始终是 `1h`。使用其他周期需导出对应的 **MANIFEST 字面量**策略文件并上传，保持 `history_window >= lookback` 且参数上限覆盖所用窗口；单改 `lookback` 不会改变信号周期。不要手改运行时 metadata 来替代 manifest 声明。

  --interval 1h --lookback 168 --entry-z 3 --exit-z 0.25 --capital 10000 \
  --data-dir research/btc_eth_usdc_multiframe_20261106/data \
  --filters research/btc_eth_usdc_multiframe_20261106/data/exchange_info.json \

已完成的框架样本为 `2026-05-01 00:00 UTC` 至 `2026-06-05 00:00 UTC`（结束不含），两币各 50,400 根真实原生分钟线。默认 1h 参数得到收益 **0.6883%**、最大回撤 **2.0541%**，8 条腿成交记录对应 **2 组配对完整往返**，手续费 0、拒单 0。它验证了策略与框架执行链路，不是充分的收益统计证据；原始结果保存在本地研究目录 `research/btc_eth_usdc_multiframe_20261106/framework_smoke/summary.json`，不随源码仓库发布。

## 一次性预热持续模拟

持续模拟共享缓存只有最近约 1,000 根分钟线，冷启动时通常不足 168 根小时线。策略会等待积累历史；可以用 [seed_pair_paper.py](../scripts/seed_pair_paper.py) 提前灌入公开行情历史。

先由管理员新建独立 `paper` 账户，选择所需策略和两币，保存最终参数，并保持停止。使用账户 ID（不是客户访问链接中的 route）。在项目目录、与后端相同的私有数据库环境变量和 Python 环境下运行：

```bash
.venv/bin/python scripts/seed_pair_paper.py ACCOUNT_ID
```

若只想检查和下载而不写入，可使用：

```bash
.venv/bin/python scripts/seed_pair_paper.py ACCOUNT_ID --dry-run
```

脚本读取进程已有的 `MK_DB_*` 环境变量；项目 `.env` 不会自动加载。不要把数据库口令或交易所密钥作为命令行参数。脚本不读取账户的交易所凭据，只用公开 Binance REST 下载原生 1m 行情。

预热分钟数为 `(lookback + 1) × 主周期分钟数`，默认每腿 **10,140 分钟**。多取一根主周期用于处理开头不完整的 UTC 桶。下载范围止于最近已闭合分钟，严格检查两腿连续、无重复、时间对齐和 OHLCV，再通过框架 `MinuteFrames` 聚合。不会执行 `on_bar`、回放历史信号、生成订单或改变初始权益。

工具仅允许停止、没有活跃执行租约、没有待处理命令，且从未产生订单、成交或任何账本的账户。已有快照即使空仓也拒绝覆盖；请新建模拟账户。下载前检查一次，写入时锁定实例并再次检查账户、策略版本、参数、租约及运行状态，任何变化都会拒绝写入。成功仅新增带来源哈希的行情快照与审计记录，账户仍保持停止；随后在管理员页面选择“恢复运行”。若旧租约尚未到期，等到过期后重试，不要手工清锁。

预热应在启动前执行；长时间搁置、参数或策略版本变更后，原历史可能不再适用。快照的 revision 与 worker 保持一致；配置 revision 改变时，worker 会清掉旧策略状态和聚合历史。新建账户重新预热可以避免覆盖旧账本。启动后的首次决策等待下一根完整主周期收盘，不追溯交易已预热的历史 K 线。

## 与研究回测的差异

框架目前不计资金费，不模拟盘口排队、部分成交或完整强平模型；零手续费不等于所有实际成本为零。研究结果含实际资金费时不能与此框架结果逐位对比。框架回测期末按最后价格估值并保留未平持仓，不强制期末平仓；末根信号也没有虚构的下一分钟成交。研究引擎按下一信号周期实际开盘计算下单数量，而本适配按闭合主周期价格提交固定数量；再加上分钟 OHLC、成交量约束、逐腿拒单及退出重试，成交明细和收益可能不同。

查看 [策略接入协议](STRATEGY_PROTOCOL.md) 可核对当前回测与持续模拟接口。这里的适配及本地验证不代表实盘验收或收益保证。
